# AI投研助手 Demo 演示指南

## 真实模式准备

1. 在 `backend/.env` 中确认 `DATA_PROVIDER=yfinance`。
2. 在本地填入 `DASHSCOPE_API_KEY`，不要在演示画面、文档或 Git 提交中展示密钥。
3. 访问 `/api/v1/health`，确认 `real_data=true`和 `qwen_configured=true`。
4. 打开 <http://localhost:5173>，顶部应显示 `REAL DATA`和当前千问模型。

如现场网络不稳定，可改为 `DATA_PROVIDER=mock`、`QWEN_ENABLED=false`，不改变七 Agent 演示流程。

## 演示目标

通过一次完整演示说明 AI投研助手如何帮助普通投资者理解公司信息、过滤财经噪音、区分事实与推断，并建立未来关注框架。演示重点不是预测股价或给出买卖建议。

## 主演示场景

用户输入：

```text
比较贵州茅台和宁德时代
```

这是普通研究问题，不触发投资行动确认，系统直接进入七 Agent 工作流。

## 完整演示流程

### 1. 任务路由与证券识别

页面 Timeline 先显示“任务路由”和“证券识别”完成，然后进入问题理解。

讲解要点：

- 识别到贵州茅台 `600519.SH` 和宁德时代 `300750.SZ`
- 识别为多股票比较意图
- 自动确定公司、财务、估值、新闻和风险等分析维度

### 2. 金融数据获取

页面 Timeline 显示“数据检索 Agent”完成。

讲解要点：

- 从 Mock Provider 获取公司资料、价格、PE、ROE、营收和利润数据
- 每项数据保留来源和截止时间
- Demo 不连接真实金融 API，避免把演示数据误用于投资

### 3. 新闻过滤

页面展示新闻过滤漏斗：

```text
候选新闻
  → 去重数量
  → 低相关过滤
  → 低可信过滤
  → 过期过滤
  → 最终保留
```

展开一条保留新闻，展示：

- 相关性
- 来源可信度
- 时效性
- 事件重要度
- 综合评分
- 保留原因
- 为什么关注这条新闻

强调“为什么关注”解释的是事件可能影响的经营变量，不预测股价上涨或下跌。

### 4. AI分析

首先展示“这家公司当前需要了解什么”，帮助普通用户建立关注问题。

随后展示：

- 公司当前画像：公司做什么、核心业务、行业和商业特点
- 小白指标词典：PE、ROE、营收增长率和净利润增长率
- 结构化横向比较表
- 当前已确认事实 Fact，并逐条显示来源
- AI Analysis，并显著说明这是模型解释而非事实
- Future Watch，列出未来需要持续观察的变量
- Scenario，使用“如果……可能……”进行条件式推演
- Uncertainty，列出当前无法确认的因素

### 5. 风险审核

页面展示风险审核清单：

- 核心事实存在来源
- 未发现确定性收益承诺
- 推断内容已标记
- 投资建议边界检查通过
- 未来情景采用条件式表达

强调证据覆盖率只代表事实来源完整程度，不代表投资判断正确率或成功概率。

### 6. 最终报告

最终报告按以下顺序展示：

1. 公司当前画像
2. 当前已确认事实 Fact
3. 这些事实意味着什么 AI Analysis
4. 未来需要关注什么 Future Watch
5. 风险因素
6. 数据来源

报告底部提供“它靠什么赚钱”“最近发生了什么变化”“未来应该关注哪些风险”“和同行相比有什么特点”等学习型追问。

## 辅助演示场景

### 投资行动风险确认

输入：

```text
茅台现在能买吗？
```

预期结果：系统不会立即分析，而是展示 Human-in-the-loop 风险确认卡。用户点击“继续分析”后才进入七 Agent 流程，最终也不会输出直接买卖建议。

### 金融术语解释

输入：

```text
茅台PE是什么意思？
```

预期结果：报告保留 PE 原始数据，并同时展示专业解释和通俗解释。

### 单公司关注框架

输入：

```text
分析宁德时代
```

预期结果：报告顶部提示关注电池价格竞争、储能业务增长和海外市场拓展，并生成对应 Future Watch。

## 演示结束总结

AI投研助手的价值不是替用户判断“买不买”，而是：

- 把复杂公司信息变得易懂
- 从信息噪音中找出重要变化
- 用来源区分事实与推断
- 帮助用户知道未来应该继续关注什么

本 Demo 使用 Mock 数据，所有内容仅用于产品演示和技术交流。
