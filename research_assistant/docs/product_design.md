# AI投研助手产品与交互方案

## 本地个人使用形态

实用模式采用 Query Router、Stock Entity Resolver 与五个专项 Agent 的七 Agent 边界，数据检索 Agent 通过 Yahoo Finance 公开数据覆盖 A 股、港股和美股，分析 Agent 可使用用户自有的千问账号生成通俗解释，研究历史仅保存在本地 SQLite。Mock 模式继续用于离线演示和自动化测试。

千问不生成或改写行情、财务事实和来源；模型返回必须通过结构化 Schema、事实 ID 引用和投资建议边界检查。外部模型不可用时，系统会保留事实层并降级到本地规则分析。

## 1. 产品定位

AI投研助手是一款面向普通投资者的公司认知辅助助手。它不以预测股价或生成买卖信号为目标，而是帮助用户降低理解公司信息的门槛，从大量财经信息中发现真正值得关注的变化，并形成可以持续更新的研究框架。

产品帮助用户完成三件事：

- 理解公司当前的业务、行业和财务状况
- 理解近期重要事件可能影响公司的哪些经营变量
- 建立未来持续关注的问题清单

产品明确不预测股价、不提供买卖建议、不替用户进行投资决策。

## 2. 用户痛点

### 2.1 看不懂

财报、公告和研报包含大量专业术语。PE、ROE、营收增长率等指标即使有数值，普通用户也未必理解其含义、适用范围和局限性。

### 2.2 找不到重点

财经新闻数量多、重复转载多、来源质量不一。用户难以判断一条信息是否与目标公司真正相关，以及它影响的是收入、成本、利润率、竞争力还是长期增长。

### 2.3 没时间持续研究

完整阅读公告、财报和行业新闻需要较多时间。普通投资者往往缺少稳定的研究流程，也容易忽略需要持续验证的问题。

## 3. 产品价值

### 3.1 降低认知门槛

系统保留原始金融数据，同时增加面向金融小白的解释层，让用户先理解指标，再阅读分析。

### 3.2 提升信息筛选效率

新闻过滤过程公开展示候选数量、去重、相关性、可信度、时效性、重要度和保留原因，让用户理解 AI 为什么关注某条信息。

### 3.3 建立结构化研究习惯

报告将事实、AI 分析、未来情景和不确定性分开，并提供 Future Watch 和学习型后续问题，帮助用户形成持续关注框架。

### 3.4 控制投资决策风险

系统不输出方向性评级和确定性买卖建议。涉及“能买吗”“该买还是卖”等行动意图时，必须经过用户确认。

## 4. 七 Agent 架构

### 4.1 Query Router Agent

在研究开始前将请求分类为公司分析、同行比较、财务分析、估值分析、风险分析或新闻解读，输出路由置信度、判定依据和该任务的报告要求。

### 4.2 Stock Entity Resolver Agent

优先识别显式 A 股、港股和美股代码，再通过 Bottom Hunter 本地证券主表、Provider 主表与远程搜索解析公司简称或全称。成功的远程结果保存到 SQLite；同名标的会要求用户补充市场或代码，不猜测。

### 4.3 问题理解 Agent

识别股票、市场、问题意图、分析维度和时间范围，将自然语言问题转换为结构化研究任务。

### 4.4 数据检索 Agent

读取公司资料、行情、估值和财务数据，记录数据来源和截止时间，并明确缺失字段。

### 4.5 新闻过滤 Agent

对候选新闻执行去重、相关性判断、来源可信度检查和时效性检查。对保留新闻计算相关性、可信度、时效性、事件重要度和综合评分，并说明保留原因与关注原因。

### 4.6 分析 Agent

在不改变原始数据的基础上生成公司画像、术语解释、投资者关注问题、已确认事实、AI 分析、条件式 Scenario、主要不确定性和 Future Watch。

### 4.7 风险审核 Agent

检查核心事实是否存在来源、Fact 与 Analysis 是否分离、未来情景是否使用条件式表达、是否存在确定性收益承诺，以及是否越过投资建议边界。

## 5. 用户交互流程

```text
进入首页并了解产品定位
  ↓
输入股票或公司问题
  ↓
识别是否包含投资行动意图
  ├─ 普通研究问题：直接进入 Agent 工作流
  └─ 投资行动问题：展示风险确认卡
                         ↓ 用户确认
                      进入 Agent 工作流
  ↓
展示七 Agent Timeline
  ↓
展示“这家公司当前需要了解什么”
  ↓
公司画像与指标解释
  ↓
Fact → AI Analysis → Future Watch / Scenario / Uncertainty
  ↓
风险因素、风险审核和数据来源
  ↓
推荐学习型后续问题
```

## 6. AI自动完成和用户确认环节

### AI自动完成

- 股票与问题意图识别
- Mock 金融数据读取
- 新闻去重和质量过滤
- 财务指标通俗解释
- 事实与来源整理
- AI 分析和条件式情景生成
- Future Watch 和学习问题生成
- 风险审核检查

### 用户确认环节

当问题包含“现在能买吗”“该买还是卖”“应该买哪个”“现在是不是买点”等投资行动意图时，系统暂停分析并显示：

> 你的问题涉及投资决策。AI可以继续帮助比较基本面、估值、事件和风险，但不会替你直接作出买卖决策。

用户点击“继续分析”后才执行完整工作流。普通信息查询不需要确认。

## 7. 风险控制设计

### 内容边界

- 不输出“建议买入”“建议卖出”等直接行动指令
- 不输出“稳赚”“保证收益”“必然上涨”等确定性承诺
- 不展示容易被理解为买卖评级的方向性结论

### 证据边界

- 所有已确认事实必须关联来源
- AI 推断必须显著标记为 Analysis
- Scenario 必须使用“如果……可能……”的条件式表达
- 未确认信息进入“主要不确定性”或“待验证因素”

### 交互边界

- 投资行动问题必须触发 Human-in-the-loop
- 风险审核展示检查项，不使用可能被误解为投资成功概率的置信度
- 页面持续展示数据截止时间和投资风险免责声明

### 数据边界

- Demo 仅使用 Mock 金融数据
- 数据来源、采集时间和行情截止时间在报告中可见
- Mock 数据不能用于真实投资决策

## 8. 基金场景迁移分析

现有七 Agent 流程可以迁移到基金认知辅助场景，但本 Demo 尚未实现基金功能。

### 可复用能力

- 问题理解：将股票代码识别替换为基金代码、基金类型和比较基准识别
- 数据检索：将公司财务数据替换为净值、回撤、持仓、行业暴露、费用和基金经理信息
- 新闻过滤：从公司事件扩展到重仓股事件、基金经理变更、监管变化和行业主题变化
- 分析：继续采用 Fact / Analysis / Scenario / Uncertainty 分层
- 风险审核：继续执行来源、确定性承诺和投资建议边界检查

### 基金场景重点指标

- 历史波动和最大回撤
- 与业绩基准的差异
- 持仓集中度和行业暴露
- 基金经理任职稳定性
- 管理费、托管费和申赎费用
- 规模变化与流动性

### 基金场景的用户关注框架

- 该基金主要投资什么资产和行业？
- 收益主要来自市场风格还是基金经理选股？
- 当前持仓集中度和回撤风险如何？
- 基金经理、规模或投资策略近期是否发生变化？
- 该基金是否与用户已有资产高度重复？

### 迁移时必须保持的边界

基金场景同样不能根据历史收益推断未来表现，不能输出确定性申购或赎回建议，也不能把风险指标包装成收益成功概率。
